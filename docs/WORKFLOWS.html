Every workflow, and what it hands to the next one

Money Maker runs eleven mostly-independent workflows — login, config production, the trading pipeline, backtesting, EOD housekeeping, and chart data ingestion. This page is the one place that shows what each does and what data one workflow writes that another reads — including the one-day delay and the pipeline that never sees the data it looks like it should.

Worth internalizing — 01

"Market data" means three different things

The trading pipeline's live broker fetch, the market_data table (⑨), and the historical_*_candles tables (⑩) are all called "market data" somewhere in this codebase. None of the three feed each other. Only the pipeline's live fetch drives trades.

Worth internalizing — 02

Two producers, one consumer, one delay

③ and ④ both write trade_config, the table ② is the sole reader of. ③ can act the same day; ④ never can — it's backtest-only and next-day-only by design, so it can extend a config chain but never start one from nothing.
