Money-Maker Strategy Rulebook

Every strategy built so far, written as algorithms: what it reads, the exact entry steps, the exact exit steps, and how it differs from its sibling. The code was the source of truth; where a doc says something else, Part C lists it.

2reserved numbers (L13–L14)
0lab results positive at t ≥ 2

Two separate numberings. "Strategy 5" in the Spring Boot app (the Pressure engine) is not "Strategy 5" in the research lab (the Foundation-Zone gate). This page prefixes them: P for production stratergy_id values, L for lab strategies/strategy_N.json files.

Terms used

TermMeaning
Settled barThe newest candle that has finished forming at the tick time. A 15-minute bar starting 09:15 settles at 09:30.
Close-signal timeapp.market.close − close-signal-offset-minutes = 15:30 − 15 = 15:15.
Swing high / low (lab)Not an N-bar pivot. A swing high confirms when a later bar breaks below the low of the candle that made the high; a swing low mirrors it. Swings alternate and are used only from their confirmation bar.
AVWAPAnchored VWAP from bar a to bar i: Σ(tp·w)/Σw, tp = (H+L+C)/3, w = volume (futures) or 1 (index).
Protected levelThe most recent unbroken swing that qualified against the trend AVWAP (uptrend: a swing low below AVWAP; downtrend: a swing high above it).
CHoCH / flipChange of character: price breaks the protected level. It is a flip (trend reverses) only if the same bar also breaks the trend AVWAP.
BOSBreak of structure in trend direction. Informational only; no strategy trades it.
SETUPAfter a CHoCH, the first bar that closes beyond the CHoCH candle's extreme while both AVWAPs (anchored at the latest swing high and swing low) slope the same way. The lab's core entry event.
touch / closeHow a level counts as broken: touch = the wick reaches it; close = the candle closes beyond it.
ROne unit of initial risk: 50 futures points (or the file's stop.futures_pts), or 5% of option premium.
Strike lockLab rule: one open position per instrument (futures contract, or expiry+strike+right). Exit processed before entry on the same candle.

A · Production app strategies src/main/java/com/moneymaker/strategy

All ten are Spring @Components, so all are registered in StrategyFactory. Whether one actually trades depends on which trade_config rows carry its id, which the code cannot tell you. Inheritance: P2 → P6 → P7; P8 → P9 → P10; P5 overrides the whole engine.

A0.1 · Per-tick scan (AbstractSmaCrossStrategy.execute), used by P1–P4 and P6–P10

  1. Transaction guard. If the strategy's entry action is BUY and transaction_type ≠ BUY, skip the config (guards P3, P4).
  2. Stop if the strike cache is empty or the config has no sma_timeframe rows.
  3. Option type from trading_side (CE/PE); ITM/OTM depth from the config.
  4. For each sma_timeframe row (interval, primary SMA period p):
    • Pick legs matching token|interval|side|…|itmDepth|otmDepth, non-empty, written by this tick.
    • Sort legs by last premium, highest first.
    • Per leg: stamp whole-day trend flags; skip if the last settled bar is not today (so a 15m series emits nothing before 09:30).
    • decision = RuleEngine.decide(...), then mapAction (identity except P4).
    • Entry-direction signals must pass the price band min_option_price ≤ close ≤ max_option_price. Exit signals are never filtered.
    • Emit TradeSignal priced at the settled bar's close, stamped with the bar's start time.

Strike set: base = floor(spot / strike_points) × strike_points (NIFTY strike_points = 100, data grid is 50). ITM base ∓ i·step for i = 0…itm_depth−1; OTM i = 1…otm_depth. Strikes of open positions are appended so exits can still fire.

A0.2 · Rule engine

ModeUsed byLogic
decideP1, P2, P4, P6, P7No SMA (or ≤ 0) → NONE. If open > SMA && close < SMA: sell rules pass → SELL. Else buy rules (ungated) pass → BUY (the exit).
decideBuyEntryP3Mirror: if open < SMA && close > SMA: buy rules → BUY. Else sell rules (ungated) → SELL (the exit).
decideWithoutCrossGateP8, P9, P10No SMA gate. Sell rules pass → SELL; else buy rules pass → BUY; else NONE.

A TradeRules passes when every required rule passes and (if non-empty) at least one anyOf rule passes. Both lists empty → fail closed.

Baseline rule sets: for p ∈ {50, 100, 200, 500}, sell = [isSma{p}DownTrending], buy = anyOf[isMarketCloseTime]. Period 20 is commented out, so an sma = 20 row trades nothing under P1–P4, P6, P7.

Whole-day trend flag (SmaTrendCalculator, maxDeviations = 0): isSmaNNDownTrending is true only if the SMA has strictly fallen on every bar since the session's first bar. One flat or rising bar kills it for the rest of the day.

isMarketCloseTime: bar is today and bar start ≥ 15:15.

A0.3 · Order admission (OrderService.handleSignal), keyed on (config, strategy)

  1. OPEN row on the same (config, strategy, option token)? Same direction → ignore. Opposite → close it at the signal price, exit_reason = SIGNAL.
  2. No open row and direction ≠ transaction_type → drop. This makes every strategy one-sided.
  3. Entry window: drop if outside entry_from … entry_to (null = unbounded).
  4. Book cap: any OPEN row in the same book_id blocks.
  5. no_of_trades: today's entries must be below the cap.
  6. max_loss: block when today's realised P&L ≤ −max_loss.
  7. no_of_parrellel_trades (same direction) and max_parallel_per_side (same CE/PE).
  8. Stop-loss day lock (P6, P7 only): a STOP_LOSS exit today blocks new entries. TRAIL_SL does not lock.
  9. Exact-duplicate guard on (config, strategy, token, direction, entry_time).
  10. Persist the row before any broker call, freezing: entry price/time, quantity, target_at_entry, stop_loss_at_entry (capped by max_sl_points), trail_ladder_at_entry, trail_atr_distance_at_entry = trail_atr_multiple × ATR (nulls the ladder), max_hold_minutes, flatten_at.

A0.4 · Position monitor (PositionService), every tick, every OPEN row

  1. Get the quote. Skip if quote.asOf ≤ entry_time: a trade never exits on its entry bar.
  2. pnl on the close; adversePnl on the bar's adverse extreme (high for a short, low for a long; live LTP falls back to close).
  3. Check in order: TARGET pnl ≥ target → TIME_STOP held ≥ max_hold → FLATTEN time ≥ flatten_at → floors: if trail_sl_at is strictly above −stop_loss, TRAIL_SL when adversePnl ≤ trail; else STOP_LOSS when adversePnl ≤ −stop.
  4. Update peak profit / loss from the favourable extreme.
  5. Raise the trail after the check (a floor earned this bar fires next bar at the earliest). Chandelier: peak − distance. Ladder "trigger:lock,…": lock of the highest rung with trigger ≤ peak.
  6. Fills: TRAIL_SL at the trail level, STOP_LOSS at the stop level (resting-order model), others at the bar close.

End-of-day force close closes every OPEN row, reason FORCE_CLOSE: 15:20 in backtest (last replay tick), 15:30 live (DaySummaryScheduler, cron 15:31).

P1

SMA cross, short premium

registeredSELLoption premiumeach sma_timeframe rowStrategy1.java

Sell an option whose premium crosses down through its SMA inside one bar, on a day when that SMA has fallen on every bar.

Indicators
SMA-p of option premium closes, p ∈ {50, 100, 200, 500}; whole-day trend flag for p.
Config
trading_side, itm_depth/otm_depth, transaction_type = SELL, price band, trade caps, target/target_pct, stop_loss/sl_pct, max_sl_points, trail_ladder, strategy_defaults(1) modes.

Entry

  1. The leg was written by this tick and its last settled bar is from today.
  2. SMA_p > 0 (warm-up complete).
  3. open > SMA_p and close < SMA_p on that bar.
  4. isSmaPDownTrending: SMA_p fell on every bar today.
  5. min_option_price ≤ close ≤ max_option_price.
  6. Emit SELL at the bar close. Legs are scanned highest premium first, so the dearest qualifying leg takes a slot when caps allow one.
  7. Order admission A0.3 applies.

Exit (first that fires)

  1. TARGET: pnl(close) ≥ entry × target_pct (PERCENT) or target points.
  2. TRAIL_SL: trail_ladder rungs on peak profit.
  3. STOP_LOSS: bar high reaches entry + min(stop, max_sl_points); fills at the stop.
  4. SIGNAL: first settled bar of the traded leg starting ≥ 15:15 emits BUY → close.
  5. FORCE_CLOSE: 15:20 backtest / 15:30 live.
  6. Re-entry allowed after any exit, subject to caps.
P2

P1 + SMA-20 slope filter

registeredSELLpremiumextends baseStrategy2.java

Same as P1 with one extra sell-side rule: the premium's SMA-20 must not be rising.

Entry

  1. P1 entry steps 1–4.
  2. sma20SlopeNotUp: NOT (sma20(t) > sma20(t−1)).
  3. Unknown means allow: if either SMA-20 is missing or the previous bar is from an earlier day (always true on the session's first bar), the rule passes.
  4. Price band, emit SELL.

Exit

  1. Identical to P1.
P3

Inverted cross, buy premium

registeredBUYrequires transaction_type = BUYStrategy3.java

Buy an option whose premium crosses up through its SMA while that SMA has risen all day. Built as the opposite-side partner of a P1 PE sell ("PE sell becomes CE buy").

Entry

  1. Fresh leg with today's settled bar; SMA_p > 0, p ∈ {50, 100, 200, 500}.
  2. open < SMA_p and close > SMA_p.
  3. isSmaPUpTrending: SMA_p strictly rose on every bar today.
  4. Premium inside the price band.
  5. Emit BUY at the close.

Exit

  1. At the first settled bar ≥ 15:15, emit SELL → SIGNAL close.
  2. Brackets mirror automatically: TARGET when premium rises by the target; STOP_LOSS on the bar low; trail as configured.
  3. FORCE_CLOSE.

vs P1: gate, trend flag and direction all mirrored by hand; a new baseline predicate would not be inverted automatically.

P4

P1's detection, executed long

registeredBUY (mapped)requires transaction_type = BUYStrategy4.java

On exactly the ticks where P1 would sell a leg, buy that same leg instead. Only mapAction is overridden: SELL → BUY, BUY → SELL.

Entry

  1. P1 entry steps 1–4 unchanged: open > SMA_p && close < SMA_p and SMA_p down all day.
  2. Emitted action becomes BUY; price band applies.
  3. Open a long at the bar close.

Exit

  1. At ≥ 15:15 the detected BUY is emitted as SELL → SIGNAL close.
  2. Long-side brackets: target on premium rise, SL on bar low, trail.
  3. FORCE_CLOSE.

vs P3: P3 mirrors the detection; P4 keeps the detection and inverts only the execution.

P5

Pressure (NIFTY 5-minute spot continuation)

registeredspot 5m7 books × 2 configssource = PRESSUREStrategy5.java

Score the latest settled spot bar on four confirming terms and one penalty. When a side reaches 3, trade the continuation on one exact option strike (or synthetic spot). One position at a time per book. Full detail: PRESSURE_STRATEGY.md.

Indicators
On spot 5m bars, session 09:15–15:30: RSI(14) Wilder; Supertrend (ATR 10, ×3); ADX(14) with ±DI and ±DI 3 bars back; session anchor = unweighted expanding mean of (H+L+C)/3 from 09:15 (default TYPICAL_MEAN); opening range = high/low of bars 09:15–09:30, complete once a bar ≥ 09:30 exists.
Books
SPOT, SELL_ITM300/200/ATM, BUY_ITM300/200/ATM; each two configs sharing a book_id.
Generator values
target 50 pts, stop 50 pts, trail ladder 25:25, entry 09:25–14:15, max hold 90 min, flatten 15:15, strike step 50, lot 75, parallel 1, per side 1.
P_down = [RSI<40] + [close<anchor] + [ST==-1] + [OR complete && close<OR_low]
         - [ADX>40 && -DI(t) < -DI(t-3)]
P_up   = [RSI>60] + [close>anchor] + [ST==+1] + [OR complete && close>OR_high]
         - [ADX>40 && +DI(t) < +DI(t-3)]
both ≥ 3 → skip;  P_down ≥ 3 → DOWN;  P_up ≥ 3 → UP;  else NONE
(NaN: confirming term scores 0, penalty not applied)

Entry

  1. Read the spot series for the config's interval; take the last session bar ≤ asOf. Stop if it is from an earlier date.
  2. Score it. Stop on NONE or both sides.
  3. Side match:
    • SPOT book: SELL config takes DOWN (short), BUY config takes UP (long).
    • Option SELL: CE takes DOWN, PE takes UP.
    • Option BUY: CE takes UP, PE takes DOWN.
  4. Strike: ATM = round(spot / 50) × 50; CE = ATM − offset, PE = ATM + offset. Try exact, −1, +1, −2, +2 steps; first key written this tick wins.
  5. Emit at the leg's last close. No premium band check.
  6. Admission: 09:25 ≤ t ≤ 14:15, one OPEN per book_id, parallel caps 1.
  7. No trades before the opening range completes (09:30 bar).

Exit (position-level only)

  1. TARGET: pnl(close) ≥ +50 pts.
  2. TIME_STOP: 90 minutes after entry.
  3. FLATTEN: time ≥ 15:15.
  4. TRAIL_SL: once peak ≥ 25, floor = +25 (armed next bar); fills at +25.
  5. STOP_LOSS: adverse extreme ≤ −50; fills at −50.
  6. FORCE_CLOSE if anything survived.
  7. A new position may open on the very next bar.
P6

Confirmed cross: P2 + 15-min confirmation, 14:45 cut-off, SL lock

registeredSELLextends P2confirmationTimeframes = {15}Strategy6.java

P2 plus two identity constants picked by replay: the 15-minute SMA-50 must not contradict, and no entry in the last half hour before the close signal. One stop-loss locks the book for the day.

Entry

  1. P2's rules: SMA_p down all day, SMA-20 slope not up.
  2. htf15Sma50DownOrUnknown: swap the leg key to 15-minute; if the series is missing, stale, not from today (every tick before 09:30), or SMA-50 ≤ 0 → unknown, allow. Otherwise the 15m SMA-50 must have fallen on every 15m bar today.
  3. entryAtOrBefore1445: bar start ≤ 15:15 − 30 min.
  4. Price band, emit SELL.
  5. Admission: if this (config, 6) had a STOP_LOSS exit today → no more entries today.

Exit

  1. As P1 (SIGNAL at 15:15, target, ladder, SL, FORCE_CLOSE).
  2. A STOP_LOSS exit triggers the day lock.
P7

P6 + first-hour regime gate

registeredSELLextends P6Strategy7.java

Do not sell a CE after a first hour that rallied more than 0.2 daily ATR, or a PE after one that fell more than 0.2 ATR.

Entry

  1. P6's rules.
  2. If the signal bar starts before 10:15 → gate is unknown, allow.
  3. sign = −1 for trading_side exactly "CE", +1 for exactly "PE", else unknown.
  4. On the underlying at the signal interval: move = close(last bar before 10:15) − open(first bar today); first bar must start ≤ 09:30.
  5. ATR = mean of the last ≤ 14 daily true ranges from sessions before today (needs ≥ 5 sessions).
  6. Allow if sign × move / ATR ≥ −0.20 (or any value is unknown).

Exit

  1. Identical to P6, including the SL day lock.
P8

"20SMA 15min candle": no cross gate, chandelier exit

registeredSELL15m onlytarget NONE · trail 2×ATRStrategy8.java

On the leg's own 15-minute premium candles, sell when the 20-bar SMA of closes is falling and the bar closes below the previous close. Exit on a 2×ATR chandelier instead of a target.

Entry (all required, in order)

  1. Config narrowed to its first 15-minute sma_timeframe row (none → WARN, nothing).
  2. is15MinuteSeries.
  3. sma20SlopeDown: mean(close[t−19..t]) < mean(close[t−20..t−1]), across sessions; needs 21 bars.
  4. closeBelowPrevClose: close[t] < close[t−1] (previous may be yesterday's last bar).
  5. Bar start ≤ 14:45.
  6. Price band, emit SELL with ATR14 of the leg (true range mean over 14 bars).
  7. No whole-day trend requirement. First possible signal: 09:15 bar, seen at 09:30.

Exit

  1. No TARGET.
  2. Chandelier: distance = 2.00 × ATR14 frozen at entry; each tick trail = max(trail, peak − distance). Governs only once strictly above −stop_loss. Exit TRAIL_SL on the bar high.
  3. STOP_LOSS: fixed stop from sl_mode/sl_pct/stop_loss, capped by max_sl_points.
  4. SIGNAL: BUY on the settled 15m bar ≥ 15:15 (in backtest this bar settles after the last 15:20 tick, so the day ends as FORCE_CLOSE instead).
  5. FORCE_CLOSE. No SL day lock.
Measured2024 engine replay (S31): 770 trades, +2,715 pts, PF 1.20. The edge sits entirely in the end-of-day close; both stop paths are net negative.

registeredSELL15mextends P8Strategy9.java

P8's signal, filtered by where the candle closed in its range, a near-ATM volume surge, and days to expiry. Gate thresholds come from strategy_defaults(9) (seeded 0.25 / 2.00 / 2); a null column switches that gate off.

B · Strategy lab research/strategy_lab

A standalone Python bench, not part of the Spring Boot build. Every strategy is a JSON file in strategies/. Signals run on NIFTY near-month futures (1m and 5m); options are priced from the signal. Results below are net ₹ after 5-pt futures / 0.5-pt option slippage per side and Zerodha charges, from results/summary.json (build 2026-09-30). "All data" means 2026 only (history_from = 2026-01-01).

B0.1 · Foundation engine (engine.py), processed bar by bar

  1. Swings. Track a running candidate high (ties move to the later bar) and candidate low. A swing high confirms at bar i when bar i breaks below the low of the candidate-high candle (touch: low[i] ≤ low[chb]; close: close[i] < low[chb]). Swing low mirrors. Swings alternate; each is usable only from its confirmation bar.
  2. Trend. The first confirmed swing sets it (swing high → down, swing low → up) and becomes the AVWAP anchor.
  3. Protected level. In an uptrend, swing lows at/after the anchor whose price is below AVWAP(anchor → swing's confirmation bar) qualify; the latest unbroken one is protected. Downtrend mirrors with swing highs above AVWAP.
  4. CHoCH. Bar i breaks the protected level (by choch_mode). It is a flip if bar i also breaks AVWAP(anchor → i) and a swing exists to re-anchor: trend reverses, anchor = latest swing high (new downtrend) or low (new uptrend), candidates rebuilt. A non-flip CHoCH keeps the trend.
  5. Use-up. Every unbroken swing that bar i breaks (by break_mode) is marked broken; then swings confirming at i are added.
  6. SETUP. For each CHoCH at bar ci, anchor two AVWAPs at its latest swing high (aH) and swing low (aL). Scan k = ci+1 … next CHoCH: the first k where
    • down CHoCH: close[k] < low[ci] and both AVWAPs fell vs k−1 → bearish SETUP;
    • up CHoCH: close[k] > high[ci] and both rose → bullish SETUP.
    At most one SETUP per CHoCH. Entry = close[k].
  7. Stop (fixed at the entry close): prev_swing = latest swing low (long) / high (short) confirmed ≤ k; choch_candle = CHoCH candle's low / high; none. A stop on the wrong side of the entry → SETUP skipped.
  8. Exit: stop checked first on each later bar (hit on break or gap; fill at the stop, at the open on a gap, at the close on a session's first bar), else the close of the next CHoCH bar in either direction.

B0.2 · Lab execution rules (lab.py)

  1. Fill: futures close of the signal bar; slippage 5 pts (futures) / 0.5 pts (options) per side; lot 65. Each scale-out tranche is charged as its own round trip.
  2. Strike lock: one open position per instrument; a signal on a locked instrument is skipped; exit before entry on the same candle.
  3. Square-off "15:25": no entry at/after 15:25; still-open positions close at the close of the 15:25 candle (eod). null = positional.
  4. Near-month: a futures position trades its entry candle's contract and closes at that contract's last candle (expiry).
  5. Option types. Via futures (_FB): bullish → long CE + short PE; bearish → long PE + short CE. Standalone (_NB): every 5 minutes pick ATR2/ATM/ITM1/OTM1 strikes, run the engine on each option's own chart, first SETUP wins, one per side.
  6. Strike pick from the spot close: ATRn = spot ± n×ATR(14) OTM rounded to 50 (default ATR2); ATM = round(spot, 50); ITMn/OTMn = ATM ∓/± n×50. Expiry = nearest weekly/monthly ≥ 1 day away. Missing strike → skipped, never substituted. Options only from 30 Jun 2026.

B0.3 · Managed position exit (lab.manage), used by L9–L12, L15–L18, L29–L30 and every learner arm

  1. R = stop.futures_pts (futures) or option_pct% of entry premium. Initial stop = entry ∓ 1R for every lot.
  2. Walk candles after the entry candle up to the cap (backtest end, contract end, or square-off). On each candle, in order:
  3. Stop (all open lots): gap or break → fill at the stop, at the open on a gap, at the close on a session's first candle. Reason stop_loss, or trail_stop once the trail has moved it.
  4. Targets: each scale_out tranche exits at entry ± target_r×R (open if gapped beyond; first candle of a session only if the close is still beyond).
  5. Trail: reached = floor((best − entry) / R). If reached ≥ start_r: stop = entry ± (reached − lag_r)×R, only tightened, effective from the next candle.
  6. No break-even move before start_r: remaining lots keep −1R after targets fill.

L1–L4

Shared algorithm

NIFTY near-month fut1 lotsquare_off 15:25lock strikeAVWAP volume-weighted

Entry

  1. On each closed bar, update swings (touch), trend and protected level (B0.1).
  2. CHoCH down when the bar's low breaks the protected low in an uptrend (L1/L2: touch; L3/L4: close below). Mirror for up.
  3. From the next bar until the next CHoCH, find the first close beyond the CHoCH candle's extreme with both AVWAPs sloping with it → SETUP.
  4. Stop = L1/L3: latest swing high (short) / low (long); L2/L4: CHoCH candle's high / low. Wrong side of the close → no trade.
  5. SETUP bar ≥ 15:25 → not taken.
  6. Enter at the SETUP close: short on bearish, long on bullish. _FB: long PE + short CE on bearish, long CE + short PE on bullish, ATR2 strike.

Exit (first that fires)

  1. Stop touched or gapped through (fill at stop / open / first-bar close).
  2. Close of the next CHoCH bar, either direction.
  3. 15:25 square-off on the entry day (eod).
  4. Contract expiry.

L3/L4 side effect: swings are still used up on a touch while the CHoCH needs a close. A wick through the protected level that closes back inside removes that level with no CHoCH, and protection falls back to an older swing.

L5–L8 · Foundation-Zone (FZ) gate

The engine runs unchanged; fz.py gates every SETUP using price zones the market sat in. TAKE = Foundation's own trade on that SETUP; REENTER = a new position from a watch. One lot, positional (no 15:25), futures only. Rules are frozen (L7/L8 accepted 2026-09-28). Build notes: FZ.md.

FZ per-bar processing, in order

  1. Retire (rooms only): on a session's first bar, retire zones with no inside close for more than room_max_age_sessions.
  2. Births. A: a band at each new protected level (bands only). B: when the last cluster_bars same-session closes span ≤ cluster_width (20 pts), a sit is born at (max+min)/2. Bands overlapping ≥ 50% merge; otherwise a band mid ± 10 pts. Rooms: see L7.
  3. Live visit: close inside the reference band continues the visit. leave_closes consecutive closes on one side end it with a LEAVE (side, far-side volume, gap flag).
  4. A LEAVE expires on a close back inside, a close across its mid, or after leave_ttl_bars.
  5. Edge events on the reference band: HUNT (close form: 1…hunt_max_bars closes outside then back in; wick form: wick beyond an edge by ≥ 0.5×ATR14 with closes inside; volume burst ≥ 1.5× visit mean when live). REJECT: wick ends within ±2 pts of an edge and the close moved toward mid.
  6. Read, first match: LEAVE → HUNT → REJECT → inside read (visit 1 = FIRST_PRINT; ACCEPTED if bars ≥ accept_bars and volume ≥ 0.8× first visit; THIN if volume < 0.5×; else RECYCLE) → PENDING → NEW.
  7. Step any open watch; then run the gate if this bar is a SETUP.

FZ gate at a SETUP in direction S

  1. Watch already re-entered on this SETUP → REENTER.
  2. BLOCK (first match): FZ position open; bar time ≥ 15:20; opening pierce (early bar crosses an edge of a band last visited on an earlier session); HUNT in direction S on this band within fade_block_bars; read NEW.
  3. TAKE branches:
    • leave: read LEAVE on side S, far-side volume ≥ sit mean, not a gap leave in the quiet open, and the band now holding the close is not RECYCLE/THIN/HUNT/REJECT.
    • first_print: read FIRST_PRINT, visit ≥ 3 bars, S = visit's entry direction.
    • defend: read ACCEPTED with a HUNT or REJECT at the opposite edge within defend_window_bars (L7/L8 add: close in the half away from the defended edge; one defend direction per visit).
  4. WATCH_EDGE: read PENDING just outside the ref band → armed watch in that direction.
  5. WATCH: a band contains the close → unarmed watch. Else BLOCK. One watch at a time.

Watch → REENTER, each later bar

  1. Cancel on a session's first bar, a leave to the opposite side, or (once armed) cancel_inside_bars closes back inside.
  2. Arm on a close beyond the band on the watch side; require leave_closes consecutive far-side closes and far-side volume ≥ sit mean.
  3. A SETUP in the watch direction on this or the previous bar of the same session.
  4. Not after 15:20 or while a position is open → REENTER at this bar's close. Stop = the Foundation rule at the fill bar; refused if wrong side or already traded through.

FZ exits

  1. Foundation stop, checked first.
  2. REENTER only: band reclaim — a close back across the watched band's mid → exit at that close.
  3. Close of the next CHoCH bar. Contract expiry. No square-off. FZ positions never overlap.

Decision loop (linear Thompson sampling)

  1. Build a setup table from one continuous engine run over the whole futures file; simulate every feasible arm for every SETUP with lab.manage.
  2. Per non-skip arm keep A = ridge·I (21×21), b = 0.
  3. Walk SETUPs in time order. First, pop every queued outcome whose exit time ≤ now and update its arm: A += x xᵀ, b += reward·x.

  5. Queue every learnable arm's outcome for this SETUP (full information, even when skipped or locked).
  6. Contract locked by the book's open position → locked.

Exit, each put candle from the entry candle

C · Where code and docs disagree

Found while writing this page. Trade-affecting items are filed in STRATEGY_ANALYSIS_TODO.md per Rule 0.

Production

  1. P5 never applies min_option_price. The generator writes 8 and the docs imply sub-8 premiums are skipped, but the band check lives in the base execute, which P5 replaces. Filed as S56.
  2. P8–P10 15:15 SIGNAL exit in backtest. A 15m bar starting 15:15 settles at 15:30, after the last 15:20 replay tick, so positions end as FORCE_CLOSE at 15:20. S31's ledger (283 FORCE_CLOSE exits) is consistent with this. Live can see the bar.
  3. P8 first bar after entry is guarded only by the fixed stop; the chandelier floor appears after the first monitored bar. If both stop columns are null there is no stop on that bar.
  4. P7 side check is exact ("CE"/"PE"); any other spelling makes the gate "unknown" and lets the entry through.
  5. 100-point ATM rounding (instrument.strike_points) on a 50-point data grid, for depth strike sets and P9/P10's volume window.
  6. Period 20 is disabled in the baseline rule set; isDistanceToNextHigherSmaAboveTarget and resolvePrimarySmaPeriod have no callers.
  7. CLAUDE.md says the changeset head is 044; 045–050 exist.

Lab

  1. "All data" is 2026 only (history_from), not five years; the 1Y preset is refused. Only the learners read from Oct 2021, from one continuous engine run.
  2. L3/L4: a touched-but-not-closed protected level is used up without a CHoCH. Filed as S57.
  3. L9–L12, L15/17/18 are not "Strategy 1's entries": sl_rule none takes SETUPs L1 refuses, and the lock drops signals while a position is open.
  4. README says L1–4 and L9–10 square off at 15:25; L11 and L12 do too.
  5. FZ zone memory starts 1 Jan 2026, not at the file's first session. Volume is live on every bar of the near-month files ("volume-blind before 26 Aug" is stale).
  6. FZ.md says the close-form HUNT is exactly one close outside; the code allows 1…hunt_max_bars (1–2 for L7).
  7. Results in the README expectations table, FZ.md §16/§19 and S43 come from older tapes; results/summary.json differs.
  8. S50 quotes −1.50L for L16's variant; the stored result is −166,620.
  9. c2c: a signal on a session's last candle enters at the next session's 09:15 open (docs say same session); its lock refuses an entry on the exit candle.
  10. Learner README says "ATR % of price"; the code uses ATR/close × 1000, capped at 5.
  11. L29/L30 JSON descriptions have mangled dash characters; S53's pullback wording was replaced by the re-emergence rule.
  12. engine.py docstring lists entry_rule/exit_rule; the engine never reads them.
